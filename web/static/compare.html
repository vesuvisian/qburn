qburn

Same caption job, two stacks — Burn end to end versus transformers.js / ONNX Runtime.

What this is (and isn’t)

Want a caption in the browser? transformers.js already does that well — export to ONNX, let ONNX Runtime drive WebGPU, ship the polished path. That’s the transformers.js demo on this site. There’s also a Node twin in scripts/tjs-cli (describe / prompt) if you want the same stack on the desktop.

qburn is narrower. Vision, fusion, and the language decoder are Burn modules in Rust. The CLI runs them on Metal or CUDA; the page is the same modules compiled to wasm on WebGPU. There isn’t a separate “web model.”

Open the Burn demo when you want to see that path in Chrome. Open transformers.js when you want the usual ONNX baseline side by side.

Where the stacks diverge

qburn transformers.js
Model Rust Burn modules you can read and step through ONNX graphs exported from Hugging Face
GPU work CubeCL kernels lowered to WGSL ONNX Runtime’s WebGPU execution provider
Page glue wasm-bindgen inside a Web Worker JavaScript calling into ORT
Weights Sharded burnpacks (usually q4-mix), Cache API ONNX files with ORT’s own quant formats
Desktop twin Same crate as cargo run -p qburn Different stack from the PyTorch training code

Why bother

If the only goal is “caption an image or short clip in Chrome,” transformers.js wins. Both demos share the same exclusive media rules (up to four images or one video with true <|video_pad|>). This project is for when you care whether Burn can carry a real multimodal model through the browser’s sharp edges — and stay honest across Metal, native WGSL, and the page instead of papering over gaps with prompt tricks.

The Burn demo runs the full instruct cascade (patches → vision → splice → decode), not a stub. Quantization, wasm32 limits, and WebGPU matmul details live on Architecture.

Speed

The Burn demo is much slower than transformers.js for a short caption. That’s a real limit, not a temporary quirk. Use the CLI when you want throughput; use the page when you want to watch the Burn path survive in a browser.
